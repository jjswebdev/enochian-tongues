# Enochian Tongues

Official website for Enochian Tongues, a metal project created in 2026.

**Live site:** https://jjswebdev.github.io/enochian-tongues/

The site uses static HTML, CSS and JavaScript, with GitHub Pages hosting and a GitHub Actions workflow that imports Facebook news. No build system or package installation is required to preview the site.

## Preview locally

From the repository root, start a simple web server:

```sh
python -m http.server 8000
```

Open http://localhost:8000/ in a browser. Serving over HTTP lets the news script load its JSON cache; opening HTML directly from disk may prevent that request.

Use the browser's responsive device tools to check phone layouts, and check the live site on a phone before major layout changes.

## Update the site

1. Edit the relevant HTML page for text or links.
2. Put new images in `assets/`, using simple filenames such as `js-portrait.jpg`, and update the page's image reference and descriptive alt text.
3. Edit `styles.css` for shared appearance changes.
4. Preview the affected page and check desktop and phone layouts.
5. Commit and push changes to `main`.

Navigation, social links and footers are repeated in each HTML file. Apply shared changes to all five pages. Musician profiles are on the **About** page.

## Publishing

GitHub Actions workflow **Sync Facebook news** publishes the site to GitHub Pages. It runs:

- When HTML files, `styles.css`, assets, scripts or the workflow itself change on `main`.
- On the schedule `23 */6 * * *` (00:23, 06:23, 12:23 and 18:23 UTC; scheduled runs may be delayed).
- Manually through **Actions → Sync Facebook news → Run workflow**.

README-only and setup-document-only changes do not trigger this workflow. Changes only to `data/` also require a manual run to publish.

The workflow fetches Facebook posts, commits a changed news cache, packages the public HTML, CSS, assets and data, and deploys them. Documentation and sync scripts are excluded from the published site.

To verify a change, open the workflow run and confirm the deployment succeeded, then refresh the live page. If needed, use a hard refresh to bypass an older browser cache.

## Facebook news feed

The home page displays up to six eligible posts as custom news cards linked to Facebook. The sync script requests up to 12 recent published Page posts, excludes hidden and unwanted entries, and saves selected display fields to the public cache.

The two posts intentionally excluded from the website are listed in `excludedPostIds` in `scripts/sync-facebook.mjs`:

- `844747345393745_122097205365125982`
- `844747345393745_639656042565400`

These exclusions do not delete the posts from Facebook. Keep the exclusions in place unless intentionally restoring those posts to the site. An empty eligible feed displays the Facebook fallback link.

If the Facebook request fails, the last saved feed is preserved and the website can still deploy. **A successful deployment alone does not prove the Facebook fetch succeeded:** check the **Fetch published Page posts** step and any **Report Facebook sync issue** warning.

The integration reads posts; it does not publish to Facebook. Likes, comments and view counters are not displayed. Facebook-hosted image URLs can expire; a later successful sync refreshes the cache.

### Configuration and credentials

In **Settings → Secrets and variables → Actions**, configure:

| Setting | Type | Purpose |
| --- | --- | --- |
| `FACEBOOK_PAGE_ID` | Repository secret | Authorized Facebook Page ID |
| `FACEBOOK_PAGE_ACCESS_TOKEN` | Repository secret | Page token used by the sync job |
| `FACEBOOK_GRAPH_VERSION` | Optional repository variable | Graph API version; defaults to `v23.0` in the current code |

Keep token values in GitHub Actions Secrets. Never place them in HTML, JavaScript, the public JSON cache, documentation or commits.

A long-lived Page token was configured on October 16, 2026. Meta reported no scheduled token expiration at that check, with a separate data-access expiration of about three months. Access can still be revoked or require reauthorization. Website edits do not require a new Facebook token.

If fetching fails, check the job's error, token validity, Page authorization, permissions and configured API version. After updating the secret, run the workflow manually and confirm the fetch step succeeds. See [Facebook news setup](FACEBOOK-NEWS-SETUP.md) for more detail.
